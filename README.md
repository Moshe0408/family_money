## מנוע ההמלצות

הליבה של המוצר. מקבל `FinanceSnapshot` ומחזיר רשימת המלצות ממוינת לפי עדיפות.

| כלל | תנאי | מקור במפרט |
|---|---|---|
| הזדמנות חיסכון | יתרה צפויה − כרית ביטחון > ₪200 | §6, §7, §49 |
| סיכון תזרים | התחייבויות > יתרה + הכנסות צפויות | §6 |
| חריגת קטגוריה | הוצאה > ממוצע × 1.25 | §19 |
| חריגת תקציב | ניצול ≥ 90% | §18 |
| פער ביעד | נדרש חודשי מול קצב בפועל | §20 |
| קרן חירום | נזיל + חיסכון < 3 חודשי הוצאות | §49 |
| מנויים | ≥ 3 מנויים מזוהים | §33 |

### הנוסחה המרכזית

```
יתרה צפויה = יתרה היום
           + הכנסות שעוד צפויות
           − חיובים צפויים (הו"ק + אשראי)
           − הוצאות שוטפות (קצב יומי × ימים שנותרו)

סכום פנוי = max(0, יתרה צפויה − כרית ביטחון)
```

רק כסף מעל כרית הביטחון נחשב פנוי. זה ההבדל בין "יש לך ₪9,800" לבין
"אפשר להעביר ₪1,500 לחיסכון".

## AI — Groq Cloud

- **מודל ברירת מחדל:** `openai/gpt-oss-120b`
- **גיבוי אוטומטי:** `qwen/qwen3.8-27b`
- **רוטציית מפתחות:** אם מפתח נדחה (401/403) או חורג ממכסה (429), הלקוח עובר למפתח הבא.

### מה נשלח למודל

רק **סיכום מצטבר**, לעולם לא שורות עסקאות:

| נשלח | לא נשלח |
|---|---|
| סכומים לפי קטגוריה | עסקאות בודדות |
| יתרות ושווי כולל | מספרי חשבון |
| יעדים ותקציבים | מספרי כרטיס |
| הוצאות קבועות | שמות בתי עסק |

ניתן לכבות לחלוטין ב־**הגדרות → עוזר AI**. כשהוא כבוי, שום נתון לא יוצא מהמכשיר.

### מפתחות

המפתחות נקראים מ־`local.properties` (מחוץ ל־git) ומוזרקים כ־`BuildConfig`:

```properties
groq.keys=gsk_xxx,gsk_yyy,gsk_zzz
groq.model=openai/gpt-oss-120b
```

ניתן גם לדרוס אותם בזמן ריצה ב־**הגדרות → מפתחות API** (נשמרים מוצפנים).

## שיתוף משפחתי

מבוסס Firebase: **Firestore** לנתונים, **Anonymous Auth** לזהות.
בלי סיסמאות ובלי הרשמה — כל מכשיר מקבל `uid` יציב, וקוד ההזמנה מחבר בין השניים.

### מבנה ב־Firestore

```
families/{familyId}              → name, ownerUid, memberUids[], members[]
families/{familyId}/data/current → כל נתוני משק הבית
invites/{code}                   → familyId, createdAt, revoked
```

### כלל התנגשויות

החלפה מלאה של הקולקציה — הכותב האחרון מנצח עבור משק הבית כולו. זה מתאים לאופן
השימוש האמיתי: בני זוג עורכים אחד בכל פעם, לא בו־זמנית על אותה שורה.

### בנייה בלי Firebase

אם `app/google-services.json` לא קיים, Gradle מקמפל את `src/nofirebase/` במקום
`src/firebase/`. האפליקציה נבנית ועובדת במלואה — רק השיתוף בזמן אמת מושבת.

## חיבור בנקים

`BankProvider` הוא ה־seam לחיבור ספק Open Banking מורשה. המימוש הפעיל היום:

1. **ייבוא CSV** — זיהוי אוטומטי של כותרות מבנקים ומחברות אשראי ישראליות,
   תמיכה ב־UTF-8 ו־Windows-1255, מפרידים `,` `;` `Tab`, ותאריכים בכל הפורמטים הנפוצים.
2. **ייבוא מ־PDF בעזרת AI** — מדביקים את הטקסט מדף החשבון, והמודל משחזר ממנו
   את העסקאות. כל שורה שחוזרת עוברת ולידציה מקומית (תאריך חוקי, סכום חיובי)
   לפני שהיא נכנסת למסד — המודל קורא, אך לא מחליט מה נשמר.
3. **הזנה ידנית** — חשבונות, כרטיסים, יתרות.
4. **סיווג אוטומטי** — לפי מילון בתי עסק ישראליים + למידה מהבחירות של המשתמש.

חיבור אמיתי דורש רישיון שירות מידע פיננסי מבנק ישראל. הארכיטקטורה מוכנה — יש
לממש `connect()` ו־`fetch()` מול ה־SDK של הספק.

## תשלום NFC

**לא ממומש, ולא ניתן למימוש בקוד בלבד.** ראו `WalletScreen.kt`.

תשלום מגע אמיתי דורש: טוקניזציה (TSP), הסמכת EMV מול Visa/Mastercard, הסכם עם
המנפיק, ועמידה ב־PCI DSS. אלה תהליכי הסמכה מסחריים.

מה שכן קיים: זיהוי יכולות NFC/HCE במכשיר, הפניה ל־Google Wallet (שכבר עבר את
ההסמכות), ומעקב מלא אחרי הכרטיסים. תואם ל־§16 במפרט (זה V2).

## אבטחה

- נעילה ביומטרית + קוד PIN (SHA-256 מומלח, 8192 סבבים)
- נעילה אוטומטית לפי זמן
- `EncryptedSharedPreferences` למפתחות ולקוד
- גיבוי ענן אוטומטי **מושבת** לנתונים פיננסיים (`data_extraction_rules.xml`)
- אין שמירת סיסמאות בנק, ואין שמירת מספר כרטיס מלא — רק 4 ספרות אחרונות
- יומן פעילות (Audit Log) לכל שינוי
